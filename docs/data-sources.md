# Trove — Data Source Map

*Created 2026-06-10. The master catalog of every data source Trove could collect, with access mechanism, permissions, collection mode, and effort. This is the working checklist for building out collectors. Update statuses as sources land.*

Status legend: ✅ built · 🔨 in progress · ⬜ not started · 🧊 deferred/icebox

---

## Collection mechanisms (the taxonomy)

Every source below uses one of these patterns. Building each *pattern* once makes every source using it cheap.

| # | Mechanism | Runs where | Examples |
|---|---|---|---|
| M1 | **One-shot file import** — user exports from a service, drops the file on Trove | App (interactive) | Apple Health export.zip ✅, Google Takeout, bank CSV |
| M2 | **Watch folder** — an external pipeline (iOS auto-export app, iCloud Drive, script) deposits files; troved ingests | troved | Health auto-export, Overland GPS |
| M3 | **Local DB/file read** — copy-then-read another app's SQLite/plist on a poll | troved | Safari/Chrome history, iMessage chat.db, Podcasts |
| M4 | **OS API watcher** — live sampling of macOS frameworks | troved | Active app/window 🔨, AFK 🔨, now-playing notifications, EventKit |
| M5 | **Cloud API pull** — OAuth/token pull of the user's own data from a service (explicit opt-in; data flows *in*, satisfying local-first) | troved | Gmail, Slack, TickTick, Spotify |
| M6 | **Agent collector** — any script/CLI/AI agent that writes spec-format files into the vault (the spec: `docs/vault-spec/`) | anywhere | Claude Code skill dumping Granola transcripts |

Permissions ladder (macOS): none → **Full Disk Access** (most local DBs) → **Screen Recording** (window titles) → per-service TCC prompts (Calendar, Contacts, Reminders, Photos) → OAuth tokens (cloud pulls).

| Browser watcher extension (tab URL + title + favicon + `audible` + referrer) | 🔨 | M4 | WebExtension (`extension/`) → native messaging → troved (host mode) → vault | M | **Chrome arm built (session 6, `browser-extensions` worktree) and smoke-tested against a temp vault; not yet installed live.** The only complete way to capture background media (e.g. YouTube playing while another app is focused) and real URLs. The extension is a dumb sensor: a `{focused, active tab (url/title/favicon/referrer/transition), audible tabs, tab_count}` snapshot every 5s + on tab/window events over a `connectNative` port; all merge logic is the `TabTracker` state machine in `trove-core::browser_ext` (unit-tested like `Watcher`/`Scrobbler`). Chrome spawns the **troved binary itself** as the host (origin arg dispatch — NM manifests can't carry args); the host is *not* the daemon and skips the watcher lock — appends go through `append_browser_visits`, now flock-per-day-file for concurrent writers. Spans record `duration_secs` (engaged = focused-active OR audible), `foreground_secs`, `audible`, plus lightweight context: `favicon`, navigation `referrer`/`transition` (active tab, via `webNavigation` — best-effort, dropped across MV3 worker restarts), and `tab_count` at span open (these four optional, omitted when empty); the host gates `focused` on system idle ≥120s. Rows are `source:"extension"` — **authoritative; `browser_timeline` drops history rows covered by a same-URL span (±120s slack), raw files keep both**. `troved install` writes the NM manifest (stable extension ID `inhhdcdmfoiodfkipnheoiejdegipgpb` via pinned key). Remaining: live install + real-Chrome validation; Safari arm (Safari 14+ runs the same WebExtension wrapped in a native app via Xcode — Trove.app can host it; its `onUpdated` audible event is reportedly flaky, the 5s poll is the fallback). Reference: aw-watcher-web (MPL). Stays separate from the activity/focus stream — never bill background playback into focus time. **Potential enrichments down the road (icebox):** browser-side `idle` state (complements the host's system-idle gate); favicon/tab-count/referrer shipped 2026-06-11. The deliberate opt-in crossing the "no page content" line now exists as the **page observer** (next row); the remaining DOM-reading observers — reading/scroll depth, media metadata (YouTube channel · length · watch %), page metadata (`og:`/author/word-count), selected text — ride that foundation as future per-feature toggles. Per-profile identity on extension rows is doable via `chrome.identity.getProfileUserInfo` (signed-in email; needs `identity` perm) or a stable `chrome.storage.local` token, but neither matches the history importer's profile-dir names (`Default`, `Profile 1`) without a URL-overlap mapping — only worth it for multi-profile users |
| Page observer — ad observation (which ads, from whom, viewed how long) | 🔨 | M4 | opt-in content scripts (`extension/observer/`) → tagged `{type:"ads"}` on the same native port → troved → `browser/ads/YYYY-MM-DD.jsonl` | M | **Built (session 2026-06-11, `chrome-extension-upgrade` worktree); live validation pending.** Spec: `docs/page-observer-spec.md`. The off-by-default second arm of the extension: enabling "Page observation" in the options page triggers Chrome's own `optional_host_permissions` consent prompt and registers content scripts dynamically — off means provably no page access (`chrome://extensions` shows "Site access: none"), and the dumb snapshot watcher is untouched either way. Performance contract encoded in the spec: top-frame-only detector, childList-only debounced MutationObserver, no polling/scroll listeners/layout reads, batched sends. Non-goals v1: no blocking, no creative capture, no YouTube/Meta native ads, no Safari. Remaining: live install + ad-heavy-site validation; later an app UI (Ads view) over the read APIs |

## Cross-cutting notes

- **Vault format conventions are now a public spec** — `docs/vault-spec/` (invariants in `conventions.md`, per-domain record formats in `domains/`, JSON Schemas in `schemas/`, an any-language collector guide in `writing-a-collector.md`; anti-drift tests in `crates/trove-core/tests/spec_validation.rs` keep spec ↔ code ↔ examples in lockstep). Shorthand: event streams → JSONL per day (`activity/` is the reference) or per month; time-series → raw + `daily.csv`; every source gets an `index.md` (human) and a `.trove/*-summary.json` (machine, rebuildable).
- **Tasks are a multi-source data type** with a normalized contract (see `tasks.rs`): any collector — Rust module, script, AI agent — plugs a new to-do app in by writing `tasks/<source>/tasks.jsonl` (current open tasks, normalized schema, only `source`/`id`/`title` required, source-specific fields under `extra`) and appending completion/creation/deletion events to `tasks/<source>/events/YYYY-MM.jsonl`. Readers scan `tasks/*/`, so no registration is needed. This is the pattern for apps with awkward APIs: even a dumb periodic export-converter gets first-class treatment in the app.
- **Correspondence is one stream** (built session 6, `correspondence.rs`): every conversation source — iMessage, email, Slack, and whatever comes next (WhatsApp exports, call history as `kind:"call"`?) — writes one unified record shape to `correspondence/<source>/YYYY-MM.jsonl` (core fields `ts/source/chat/sender/from_me/kind/text`, source extras optional). New message-like collectors must write this stream, not invent their own.
- **Cloud pulls are standalone-safe.** The standalone rule bans external *runtime apps/processes*, not pulling your own data in via APIs/libraries (vision doc: "heavy use of CLIs/APIs/MCP for collection"). Tokens live in `.trove/` (or Keychain), pulls are opt-in per source.
- **OAuth app credentials & distribution** — decided, see `docs/oauth-distribution.md`: official builds bake per-provider credentials in at compile time (CI secrets → `option_env!`), bring-your-own credentials is the always-available fallback, and a token-exchange proxy is rejected unless a paid sync tier ever exists to host it.
- **Google is one integration entity** (decided 2026-06-11; full design + API-landscape research in `docs/google-integration-plan.md`). One OAuth client, multi-account, minimal read-only scopes added incrementally (no preemptive Drive/Docs — re-consent later is one click). v1 = Gmail, Calendar, Contacts (+Other contacts), Tasks, YouTube, Books; follow-on = Google Health API (rebuilt Fitbit API); later = the **Data Portability API** — an automated Takeout (Search history, YouTube watch history, Maps/Play/Chrome data, recurring 30/180-day grants) that is currently **EU/UK-only**, so it's a region-gated future source. Docs/Sheets/Drive deferred by doctrine (complete data, not in-progress drafts). Dead ends with no automated route: Photos library (API closed Mar 2025), Maps Timeline, Keep, Pay/Wallet, Assistant/Gemini activity.
- **Copy-then-read** every third-party SQLite DB (they're locked/WAL); never write to them.
- **Permissions onboarding** is a product feature: a Settings pane showing each source, the permission it needs, and a deep link to System Settings. Build it generic with the Safari-history work.
- **Backfill vs. stream**: for each source note what's recoverable later (exports, DBs) vs. lost forever if not captured live (now-playing, window titles). Prioritize the unrecoverable.
